# Complemento ao Manual de Uso — Produção após release #352

> Referência operacional: produção em 22/10/2026, commit `f8610c26`. Complementa os capítulos M2.1–M2.8 sem substituir os procedimentos já documentados. Os recursos visíveis dependem das permissões efetivas de cada usuário.

## Membros — listagem, pesquisa e filtros

1. Acesse **Mais → Membros**, se o seu perfil possuir permissão.
2. Na listagem, utilize o campo **Buscar membro ou Casa** para localizar registros autorizados. A pesquisa aceita nomes com ou sem acentos: por exemplo, `andre` pode encontrar **André**.
3. Também é possível pesquisar por referência da Casa de Oração, inclusive por código, conforme os dados permitidos para seu perfil.
4. No filtro **Filtrar membros por Setor**, selecione um setor para restringir a consulta territorialmente. Os registros e os dados de cada membro continuam sujeitos às permissões da conta.
5. Se a listagem tiver várias páginas, utilize os controles de navegação. A pesquisa e os filtros são aplicados ao conjunto de registros autorizado, não somente à página exibida.
6. Caso a API apresente erro ao consultar nova página ou filtro, a tela informa a falha e não reapresenta como resultado atual a listagem obsoleta. Para repetir a consulta, altere o filtro, o texto da busca ou a página; se o erro persistir, informe a mensagem ao suporte sem expor dados pessoais.
7. A exclusão de membro com vínculos institucionais ou históricos pode ser bloqueada; utilize o procedimento autorizado de inativação quando aplicável, sem contornar as regras de integridade.

## Eventos — ordenação

1. Em **Gestão de Eventos**, confira os filtros territoriais, de status e de período.
2. Use as colunas **Início** e **Título** para alternar a ordenação crescente/decrescente.
3. A mudança de ordenação mantém os filtros ativos e altera apenas a apresentação dos eventos autorizados.

## Suporte

Ao comunicar incidente, informe a tela, o horário, o comportamento observado e a versão/build exibidos pelo sistema; inclua o código da tela e a mensagem de erro somente quando estiverem visíveis, sem divulgar PIN, dados pessoais, tokens ou links de ativação.
